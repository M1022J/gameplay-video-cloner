# Field Lessons — 实测复盘附录（末日生存房车 Maker 复刻，2026-10-25）

> 本附录来自一次真实的完整复刻（TapTap Maker / UrhoX / Lua 交付，非 HTML）。
> 上一轮按主文档三轮流程做完并「构建成功」，却在真机首测翻车两次（点不动、比例被骂）。
> 以下每条都是用返工换来的硬规矩，按主文档流程执行时**必须叠加**本附录。

## 1. 逐帧分析协议（Round 1 强化，替代「16 帧够用」的错觉）

16 张关键帧只能看布局，看不到规则。Round 1 必须产出**事件表**：

| 字段 | 说明 |
|---|---|
| 事件 ID | 如 E014，全项目引用统一 |
| 时间戳 | 视频内秒数 + 帧号 |
| 输入 | 玩家做了什么（点哪个按钮/拖拽到哪） |
| 前状态 → 后状态 | 数值变化逐项写（货币 1300→1105 这类） |
| 证据出处 | 帧文件路径 |
| 结论等级 | **观察到 / 重复验证 / 推测 / 未知** 四档，视频没展示的一律「未知」 |

执行要点：

- 先场景切换检测 + 1fps 全扫，再对每个 UI 交互点前后 ±2 秒做原生帧率密抽。
- **数字只能来自 OCR 或像素量测**，禁止代理「看图说话」读数——曾有代理把铜币 1300 反复读成 300。
- 每个修复/实现项必须关联事件 ID；状态只认截图/日志证据，不认文字描述。
- UI 元素全清单：视频里出现的**每一个** UI 元素（按钮/面板/图标/牌子/进度条/徽标）
  都要裁图存档 + 规格（位置、尺寸、颜色采样、状态数），并逐项登记处置方式：
  `生成素材 / 程序绘制（须注明理由） / 待定`。清单没清零不许进 Round 3。

## 2. QA 门：双层无头 harness（构建成功 ≠ 游戏能玩）

远端构建只验编译。交付前必须用无头 harness 加载**真实游戏脚本**（引擎 API 全部桩掉），
用状态驱动的方式把主流程和**每一个界面**都点一遍：

- 逻辑层：数值链（价格、周期、产出）逐项断言。
- 界面层：每个面板打开/关闭、每张卡片、每个对话框按钮都要真实命中测试——
  上一轮旧版曾因建造菜单布局变量少写一个值、一点就黑屏，逻辑层全过、界面层没测就漏了。
- **设备变体必须进 harness**：至少 DPR=1 与 DPR=3 两档各跑全流程（见 §3 的惨案）。
- 断言失败数必须为 0 才许构建；每批构建留前后对比证据存档。

## 3. 输入坐标铁律（NanoVG/引擎类项目通用）

**引擎返回的鼠标/触摸坐标是物理像素。** 任何设计分辨率/逻辑分辨率映射前，
必须先 `logical = input / DPR`，再做 letterbox/缩放逆变换。

惨案实录：绘制用了 DPR 修正（画面正常），输入没除 DPR——真机（DPR≈3）上
所有点击坐标被放大 3 倍全部落空，表现为「开始游戏点了没反应」，
而桌面 DPR=1 的测试全程绿灯。此类 bug 只有高 DPR 变体测试或真机能抓到。

## 4. 美术素材纪律

- **比例以实机渲染帧量测为准**，不以素材画布尺寸/骨骼名义尺寸为准。
  名义画布高 ≠ 实际绘制高（透明边、留白都会骗人）。关键比例（人物/载具/轮子）
  在合成图上量完再定缩放。
- 载具类多段拼接素材（车尾+可重复中段+车头）要预先定义锚点与裁切规则；
  生成图常带透视，先修成正侧面再用。
- 窗户/玻璃类素材必须**真透明**（alpha 通道可透见内部），
  生成模型画的「假窗景」要用确定性修图（抠除+程序窗框）解决，不要反复重抽碰运气。
- 轮子等旋转件：正圆画布 + 一个可辨识标记点，旋转才读得出来。
- 素材处置结论要落盘成 geometry 记录（关键分数坐标），代码与素材共用同一份数值。

## 5. 版权/归属红线

原版游戏里的**发行方公司名、登记号、版权行、官方群号**是原发行方的身份信息，
不是玩法内容。1:1 复刻时逐项登记、**一律不抄进复刻版**（适龄提示等通用合规元素除外，
且用通用样式）。曾因照抄标题底部版权行被用户当场质疑。

## 6. 引擎适配注记（非 HTML 交付时）

本 skill 默认产物是单文件 HTML；当目标平台是 TapTap Maker（UrhoX/Lua）等其他引擎时：

- 三轮流程、蜂群分工、台账、QA 门全部照用；只有 Round 3 的 merge 步骤
  替换为 **Lead 亲手集成**（各专家模块按接口契约拼装，跨模块契约冲突由 Lead 修，
  并把每处修正记进 SDD 台账）。
- `validate_architecture.py` 面向 HTML 产物结构，非 HTML 项目以 §2 的 harness 为 QA 门，
  并在台账注明替代关系，不要硬套脚本报错充数。
- 子代理分工必须给**隔离上下文包**（SHARED_FACTS 只放已核实事实 + 各自任务书），
  并明确每个代理只能动自己的文件；Lead 对交付物做行数/语法/冒烟抽查，不全信自述。

## 7. 汇报纪律

- 进度主动实时汇报，不等用户追问。
- 结论只基于亲眼证据或可复现的功能证据；「构建通过」「截图看起来正常」都不算数。
- 出错承认一次、说清根因和防复发措施，不软化、不甩锅给工具。
