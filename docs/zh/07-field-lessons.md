# 07 · 实测复盘：把流程做对的硬规矩（2026-10-25）

本篇是 skill 在真实项目（末日生存房车，TapTap Maker / Lua 交付）完整跑完一轮后的复盘，
完整版见 `skill/references/field-lessons-maker-replication.md`，这里是速查版。

## 七条硬规矩

1. **逐帧事件表**：Round 1 不止 16 帧。每条规则进事件表（事件 ID/时间戳/输入/
   前后状态/证据/结论等级：观察到、重复验证、推测、未知）。数字只信 OCR 与像素量测。
2. **UI 元素全清单**：视频里每个 UI 元素裁图建档，逐项登记「生成素材 / 程序绘制（注明理由）」，
   清单清零才进 Round 3。
3. **双层 QA 门**：构建前用无头 harness 加载真实脚本，逻辑数值 + 每个界面点击都测；
   远端构建成功只证明能编译，不证明能玩。
4. **DPR 变体测试**：harness 至少跑 DPR=1 与 DPR=3 两档全流程。
5. **输入坐标先除 DPR**：引擎给的触摸/鼠标坐标是物理像素，不除 DPR，
   真机上所有按钮都会偏掉数倍而点不中（本项目实测翻车一次）。
6. **比例量测为准**：人物/载具/轮子比例在渲染合成图上量，不信素材名义画布尺寸。
7. **不抄原发行方身份信息**：原版的公司名、登记号、版权行一律不进复刻版。

## 非 HTML 交付的适配

目标引擎不是浏览器时（Maker/Lua、Unity 等），三轮流程与台账照用；
Round 3 的 HTML 合并替换为 Lead 按模块契约亲手集成，跨模块修正逐条记入 SDD 台账；
QA 门以双层 harness 为准，并在台账注明与 `validate_architecture.py` 的替代关系。
