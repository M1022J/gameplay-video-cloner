# 08 · 图片反推玩法（第三版增补）

## 要解决的问题
前两版都靠视频。第三版补上「只有一张截图也能开工」：从静态图反推玩法规则，
生成可验收的规格与特性矩阵，复刻完再用像素级打分验收还原度。

## 流程（接在 Round 1 最前、Round 3 最后）
1. **视觉可供性矩阵**（参考 01）：按符号学把画面元素映射到机制——可交互物、
   危险物、收集物、HUD 状态各自对应什么玩法。
2. **净室侦察**（Jakeschincariol/replica-skill 的 replica-recon/design）：只看图、
   不看源码，产出功能清单与规格（对应 `infer_gameplay_from_image.py` 的
   recon_gameplay_spec.json + features.csv）。
3. **图层分类表**（yuzhworkhard-wq/image-to-code 的硬规则）：背景/实体/HUD/特效
   分层 + 像素坐标量测；精灵必须是干净透明底 PNG（`audit_png_assets.py` 审计）。
4. **13 节 GDD 合成**（yakoub-ai/phaser4-gamedev 的 phaser-gdd + DY-2026/GameDesignOS
   的设计 skill 群）：把侦察结果写成完整游戏设计文档再动工。
5. **试玩闭环验收**（kursku/develop-web-game + caucy2026/game-playtest）：
   自动试玩截图 → `imgdiff_parity.py` 与原图逐屏打分（replica-diff 思路），
   不达标回炉。

## 三个新脚本（skill/scripts/）
| 脚本 | 输出 |
|---|---|
| `infer_gameplay_from_image.py`（需 opencv） | `recon_gameplay_spec.json` + `features.csv`（must/should 特性矩阵，含验收方式列） |
| `imgdiff_parity.py`（需 opencv） | 还原度 JSON（feature_parity_score、shippable 布尔）+ 可选差异图、按 features.csv 的逐项核对 |
| `audit_png_assets.py` | 每张 PNG 的 alpha 通道、角部 alpha、透明像素比与 `transparent_bg_ok` 判定 |

本仓整合时已用真实截图实测：三脚本均正常产出（规格+特性矩阵生成、还原度打分输出、
无 alpha 的截图被正确判定为透明底不合格）。
