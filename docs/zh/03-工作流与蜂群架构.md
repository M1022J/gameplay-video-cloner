# 03 · 工作流与蜂群架构

## 三轮流水线

### Round 1（地基）：视频遥测 + 契约锁定 + 任务拆解
- `analyze_gameplay_video.py` 抽关键帧：16 帧接触表、时间方差图（静态 HUD 带 vs 动态战场）、
  场景切换点（相邻帧平均像素差 > 42.0）、6 色主色板，汇总为 `telemetry.json`
- 锁定全局契约：`Constants`（画幅、色板、速度、安全区）、`EventBus`（on_hit / on_merge /
  on_pickup / on_land / on_level_up / on_death）、`GameState`（含确定性 `reset()` 与
  `window.render_game_to_text()` 自检接口）
- 用 `orchestrate_subagents.py` 生成 5 个子 Agent 的隔离任务包，用 `swarm_task_board.py`
  建 DAG 任务板：任务 1 完成自动解锁任务 2/3/4，三者完成解锁任务 5

### Round 2（并行）：三个专科子 Agent 同时开工
| 子 Agent | 负责 | 关键纪律 |
|---|---|---|
| subagent-02 物理/控制器 | 移动、碰撞（圆/AABB 4–6 子步松弛）、敌潮调度 | dt 归一化；80ms 土狼时间、100ms 跳跃缓冲（平台类） |
| subagent-03 骨骼/美术 | 2D Spine/Rive 骨骼或 3D 程序化 rig、两骨 IK、Juice 反馈、粒子 | 只经 EventBus 通信；震屏只作用于渲染变换不碰物理坐标 |
| subagent-04 HUD/音频 | HUD 安全区内的计分/血条/飘字、参数微调抽屉、Web Audio 合成音效 | 触控目标 ≥44×44px；音频手势解锁 |

### Round 3（收口）：两阶段审查 + 组装交付
- 阶段一 规格合规：视频里的机制/骨骼状态/HUD 元素是否全实现，零 TODO/FIXME 占位
- 阶段二 代码质量：帧率无关、热循环零分配（对象池）、reset 干净
- 3 点抽查（`merge_subagent_modules.py`）：是否越界写别人命名空间、导出是否对契约、有无占位符
- 架构门禁（`validate_architecture.py`）：8 项检查须 ≥7 过（本仓实测样例为 8/8）
- 三方共识平衡审计：判定框 75–80% 视觉尺寸、软锁率 0%、与源视频对比度
