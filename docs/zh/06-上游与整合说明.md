# 06 · 上游与整合说明

## 整合原则
1. **按引用收录**：skill 真正引用的内容全收；巨型综合仓（数千个无关 skill）只收被引用的那一个，
   并在 `SOURCES.md` 里写明原仓地址与固定 commit，需要其余内容可按 commit 回上游取。
2. **不改原文**：整合时只去掉 `.git`，不改写上游任何文件；每个目录保留其原 LICENSE。
3. **可溯源**：`SOURCES.md` 记录全部 14 个来源的 URL、commit SHA、收录范围与例外。

## 手册的两处笔误（已核实）
- `kieranklaassen/orchestrating-swarms` 不是 GitHub 仓库，其实是作者的一篇 Gist
  （Claude Code Swarm Orchestration Skill），本仓按 Gist 原文收录于 `upstream/orchestrating-swarms/`。
- `qodex-ai/multi-agent-orchestration` 仓库不存在；正确仓库是 `qodex-ai/ai-agent-skills`，
  其中同名 skill 目录才是引用对象。

## 已知例外
- PlayableIntelligence/game-creator 的 `assets/`（140MB）、`examples/`（70MB）未收录（本 skill 未引用）；
  其 `skills/playdotfun`、`skills/unity-mcp` 是指向未初始化 submodule 的符号链接，一并略过。
- 16 个二进制媒体（演示 gif/mp4、图例图）未随 GitHub 上传（通道只收 UTF-8 文本），
  清单见 `docs/BINARY_FILES.md`；本地整合包中完整存在。
